문제

DB와 k8s 버전 지원이 끝나 가고 있었습니다. 놔두면 연장 지원 비용이 붙고, 마이너 버전은 기한이 지나면 원하지 않는 시점에 강제로 업그레이드됩니다. 고객사 페이지에 저희 위젯이 붙어 있어서 DB가 멈추면 고객사 화면도 같이 멈춥니다. 멈추는 시간을 최소로, 그리고 되돌릴 수 있게 하는 게 기준이었습니다.

Aurora MySQL 5.7 → 8.0

5.7 표준 지원이 끝나면 연장 지원에 자동 등록되고 vCPU 시간당 $0.12가 붙습니다. 운영 DB(vCPU 4개) 기준 월 약 $345였습니다. 방식은 다운타임을 예측할 수 있는 블루/그린으로 정했습니다.

사전 검사

  • MySQL Shell checkForServerUpgrade로 호환성 검사. 개발 DB 스냅샷 기준 에러 21건·경고 388건이 나왔고, 종류로 묶으면 에러 2종·경고 4종
  • 에러: RDS가 관리하는 테이블의 스키마 불일치는 테스트 DB로 업그레이드해 보고 영향 없음을 확인, 폐기된 날짜 구분자를 쓰던 파티션은 쓰지 않는 파티션이라 삭제
  • 경고: utf8mb3 폐기 예정, 예약어가 된 컬럼명, 0 날짜 값, mysql_native_password 폐기 예정. 업그레이드는 막지 않지만 운영 중 문제가 될 수 있는 것들이라 따로 정리

블루/그린 준비

  • 블루(기존)에 binlog_format=ROW. 적용에 재부팅이 필요해 writer → reader 순으로 재부팅해서 읽기는 끊기지 않게
  • 그린 파라미터 그룹은 event_scheduler=OFF, read_only=1로 복제 충돌을 막고, 문자셋·타임존은 기존과 똑같이 맞춤. 전환 뒤 두 값을 되돌림
  • 운영 스냅샷으로 리허설: 그린 생성 약 45분, 전환 40초 ~ 2분

당일

  • 00:00 DB에 쓰는 배치를 멈추고 ALB에서 점검 응답
  • 00:08 재부팅 완료, 그린 생성 시작 → 01:18 생성 완료 → 01:22 전환 완료
  • 01:25쯤 고객사 페이지 정상 확인. 점검창 4시간 중 1시간 반 안에 끝남

남은 것

  • 그린 생성이 리허설 때보다 오래 걸림(예상 50분 → 실제 70분). 다음부터 여유를 더 잡음
  • 점검 페이지 다국어를 챙기지 못해 해외 고객사 페이지에 한국어 안내가 나감
  • k8s 노드를 재시작하면서 점검용 ALB 규칙이 사라져 다시 걸었음. 노드 재시작은 마지막 순서로
  • 블루/그린은 전환 뒤엔 되돌릴 수 없어, 그 뒤에 문제가 나면 어떻게 빨리 되돌릴지 더 고민했어야 했음

Aurora 마이너 업그레이드 (3.08.1 → 3.10.3)

Aurora MySQL은 마이너 버전마다 지원 기간이 다르고 연장 지원이 없습니다. 기한이 지나면 운영 중 원하지 않는 시점에 강제로 업그레이드됩니다. 한 번은 RDS for MySQL의 지원 일정을 Aurora 것으로 잘못 읽어 공유했다가 정정했습니다. 그 뒤로는 Aurora 릴리스 캘린더만 봅니다.

사전 검사

  • mysqlcheck로 폐기된 데이터 형식, 고아 .frm, 정의자 없는 트리거 확인
  • MySQL Shell은 대상 버전과 같은 버전(8.0.42)으로 설치해서 검사. 에러·경고 0건
  • 운영 스냅샷으로 개발 서버에서 in-place로 해 보면서 캐시를 피하는 API 요청을 계속 보냄. 요청·커넥션 실패 0, 전환 순간 지연 20초
  • 나중을 위해 binlog_format도 이번에 바꿀까 했지만, 검증 없이 넣을 변경은 아니라서 뺌

당일 (예정 → 실제)

  • 02:25 배치·헬스체크 중지 (2분)
  • 02:50 수동 스냅샷 (4분)
  • 03:01 in-place 업그레이드 (3분)
  • 전 서비스 재시작으로 DB 재연결 확인, 어드민만 먼저 열어 QA (라이브·VOD 생성·수정·삭제 정상)
  • 03:16 점검 해제, 03:26 배치 원복. 04:00까지 잡은 작업이 03:30 전에 끝남

RabbitMQ 3.11 → 4.1

  • RabbitMQ를 재기동하면 앱이 재연결을 못 해서 전 서버를 재시작해야 했습니다. 앱 재연결 로직부터 넣었습니다
  • 새 클러스터를 만들고 Federation으로 기존 큐를 이어 붙인 뒤 영향이 낮은 서버부터 옮김
  • 롤백은 Federation 해제 + 기존 클러스터로 재배포

EKS 1.34 → 1.36

  • 위험한 건 당일 밖으로. 기존 버전에서도 안전한 교체(애드온, 노드 관리 도구, 노드 이미지)는 며칠 전에 끝내고 당일엔 컨트롤 플레인과 노드만 남김
  • 롤백할 수 있는 마지막 시점을 개발 서버에서 확인해서 미리 정해 둠
  • Terraform은 단계별 커밋을 체크아웃해서 apply. 브랜치 끝에서 apply하면 뒷단계 변경까지 한꺼번에 들어갑니다
  • 점검 공지, 점검 응답, 배치 중지 없이 무중단. 예상 1시간 40분 → 52분

돌아보면

런북에 예정 시각과 실제 시각 칸을 같이 뒀습니다. 예상 50분이던 블루/그린 생성이 당일엔 70분 걸리기도 했습니다. 다음 작업 때는 이 차이를 보고 시간을 잡습니다.
