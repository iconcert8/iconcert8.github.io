문제

라이브 방송은 시작하는 순간 시청자가 한꺼번에 들어옵니다. 모든 서버가 ALB 하나에 붙어 있었습니다. ALB 자체 오토스케일로는 급격한 트래픽을 못 버텨서 방송 전에 용량(LCU)을 미리 올려 둬야 했고, ALB 하나에 문제가 생기면 모든 서버가 같이 영향을 받는 구조였습니다.

  • 대기열은 비즈니스상 둘 수 없는 서비스라, 미리 늘려서 받아 내는 수밖에 없었습니다
  • AWS와 협의해 LCU를 미리 예약할 수 있는 권한을 받고, 고객사 마케팅 일정에 맞춰 수동으로 올리고 있었습니다

원인

어디를 뗄지는 감이 아니라 데이터로 정하고 싶었습니다. ALB 로그를 분 단위, 도메인별로 집계했습니다. 방송 시작 직후 1분은 홈 + 플레이어 요청이 70%였습니다. 그 뒤로는 통계 ping 비중이 커졌습니다. 진입할 때 몰리는 건 홈·플레이어였습니다.

  • 20분 합계로 보면 통계 ping이 가장 많고, 분당 최대도 통계 수집 서버(시작 2분 뒤 16만 건)
  • 정리하면 진입 순간은 홈·플레이어가, 그 뒤 유지 구간은 통계 ping이 끌고 감

Route53 가중치로 ALB 두 개에 나누는 안도 봤습니다. DNS 캐시 때문에 실제로는 고르게 안 나뉠 거라 판단해서 뺐습니다. 캐시 TTL을 줄이면 응답 지연과 DNS 쿼리 비용이 늘고, 같은 설정의 ALB를 복제하는 거라 한쪽 문제를 막아 주지도 못합니다. 서버마다 ALB를 하나씩 주는 것도 비용 때문에 뺐습니다. 서버별 요청량을 보고 방송 진입, 통계 수집, 그 밖의 서버로 묶었습니다.

작업

1차 분리 (2025.08)

  • 홈·플레이어를 별도 ALB로 분리. 한 번에 다 하지 않고 1차로 떼고 실제 LCU를 본 뒤 다음을 판단
  • 서버끼리 호출하면서 ALB를 다시 타던 경로를 클러스터 내부 주소로
  • 리스너 규칙 순서 조정. ALB는 요청마다 규칙을 위에서부터 검사해서, 요청이 많은 서버를 앞으로 올림. 평시 규칙 검사 약 1만/s → 3천/s, 방송 중엔 요청당 검사가 약 1/4
  • 분리 뒤 실측(동접 2.1~2.6만에 기존 ALB 240, 방송용 500 LCU)에 맞춰 ALB별 예약값을 다시 나눔. 기존 ALB 200 → 100, 방송용 200

서버 쪽

  • 증설로 안 풀리던 Redis 호출을 로컬 캐시로. 서버마다 DB·API로 직접 웜업하면 서버 수만큼 원본 부하가 늘어서, Redis를 원본으로 2초마다 동기화하게 함. 같은 동접에서 Redis 호출 30% 감소
  • 세션 생성 경로 단축. 방송 → API(DB) → 플레이어 → API → 방송이던 경로를 방송 → 플레이어 → 방송으로. DB를 거치던 검증을 로컬 캐시로
  • 서버 기동 시 주요 API를 한 번씩 호출하는 웜업. 증설 직후 순간 지연(10초 평균) 400~500ms → 200~300ms, 약 40% 감소

캐시 웜업의 함정

좋아요 설정을 삭제했는데 화면에 계속 남아 있었습니다. 캐시 TTL은 20초였는데 사라지지 않았습니다. 웜업 스케줄러가 DB가 아니라 캐시가 걸린 함수를 호출해서 값을 다시 캐시에 넣고 있었습니다. 스케줄러는 8초마다 돌았고, TTL 20초가 끝나기 전에 매번 다시 채워졌습니다. 캐시가 캐시를 바라보니 TTL이 영원히 연장됐습니다. 캐시가 안 걸린 함수로 웜업하도록 고쳤습니다.

2차 분리: 통계 수집 서버 (2026.10)

1차 뒤 기존 ALB 예약을 실측에 맞춰 낮췄습니다. 그런데 2025년 11월 대형 고객사 방송에 미리 알지 못한 트래픽이 몰렸고, 예약 100 LCU였던 기존 ALB가 실제로는 500 LCU까지 올라가며 TLS 협상 오류가 27만 건 났습니다. 방송용 ALB는 정상이어서 방송 접속은 유지됐습니다. 분리 덕을 본 실제 사례였습니다.

  • 기존 ALB를 7일치 보니 요청 3,024만 건 중 2,803만 건(93%)이 통계 ping. LCU를 가장 많이 잡아먹는 항목도 ping이 새로 여는 연결 수였음
  • 통계 수집 서버 전용 ALB를 만들고 DNS를 전환. 기존 ALB에 남은 통계 요청이 0이 된 걸 확인한 뒤 기존 규칙을 지움. 규칙이 남아 있는 동안은 DNS만 되돌리면 롤백
  • 기존 ALB 예약분은 통계 ALB로 옮김. 예약 합계는 그대로
  • 분리 뒤 통계 트래픽이 유독 몰린 방송에서 통계 ALB가 잠깐 응답하지 못했지만, 다른 ALB와 서버는 정상이라 방송 운영에는 영향이 없었음

결과

  • 같은 동접 기준 LCU 약 10~20% 감소(동접 약 1.8만 명 기준 700 → 200 + 280). 다른 날 비교한 추정치라 추세 정도로 봅니다
  • 분리 전엔 동접 약 3.4만 명에 LCU 900을 한 ALB가 받았는데, 분리 뒤 동접 약 6.1만 명 방송은 두 ALB가 270 + 750으로 나눠 받음
  • ALB가 나뉘면서 한쪽 문제가 다른 쪽으로 번지지 않게 됨
  • 2차 분리 뒤 같은 동접(2만 명 이상) 1분 중앙값으로 기존 ALB LCU 13.4 → 0.2. 기존 ALB가 방송에 반응하지 않게 돼 그쪽 사전 예약을 없앰
  • 기존 + 통계 ALB LCU 합은 13.4 → 12.0으로 늘지 않음. 늘어난 비용은 ALB 1대 시간 요금. 통계 요청당 규칙 검사 2 → 1회

돌아보면

1차 때는 다른 날 숫자를 비교해서 추세라고밖에 말하지 못했습니다. 2차 때는 분리 전후 7일을 같은 동접 구간끼리 1분 값으로 비교했습니다. 사전 예약은 여전히 고객사 일정에 기대고 있어서, 대형 방송을 미리 알려 달라고 고객사에 요청해 두었습니다.
