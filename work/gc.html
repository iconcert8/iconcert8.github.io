문제

API 서버가 간헐적으로 느려졌습니다. GC 그래프를 보니 STW가 500ms~1초씩 튀었고 느려진 시점과 겹쳤습니다. 힙도 고정값이라 컨테이너 메모리를 늘려도 힙은 그대로였습니다.

원인

Parallel GC를 쓰고 있었습니다. 처리량을 우선하는 GC라 young, old 수집 모두 애플리케이션을 멈추고, 힙이 클수록 오래 멈춥니다. 저희한테 필요한 건 처리량보다 짧게 멈추는 거였습니다.

작업

  • Parallel GC → G1GC
  • 힙을 고정값 대신 컨테이너 메모리 비율로 (MaxRAMPercentage)
  • 서버 8개. 한 번에 바꾸지 않고 모니터링하면서 단계적으로 배포

결과

  • STW: 500ms~1초 → 10ms 이하
  • 대신 GC 횟수는 30분당 4회 → 8~9회로 늘었습니다. 한 번에 길게 멈추는 것보다 짧게 자주 멈추는 게 요청 지연에는 훨씬 낫다고 판단했습니다
  • 이후 리사이징 때 JVM 설정을 따로 안 고쳐도 힙이 컨테이너를 따라갔습니다
